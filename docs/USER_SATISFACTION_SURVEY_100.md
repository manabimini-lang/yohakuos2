# YOHAKUOS サービス満足度調査（100人利用を仮定した仮説レポート）

作成日：2026-08-30
対象：YOHAKUOSを4週間以上利用したユーザー 100人（想定）
目的：次のプロダクト改善の優先順位を決める

> **重要**：本資料の数値・自由回答は、実査前の「仮説データ」です。実際の顧客の声やプロダクトKPIとして外部に引用せず、調査票・分析設計のたたき台として利用してください。

## 1. 調査設計

- 回答方法：アプリ内アンケート（利用4週目、任意回答）
- 回答者：100人（回答率100%と仮定）
- 主な設問：5段階満足度、継続意向、NPS、機能別評価、自由回答
- 利用頻度の内訳（想定）：ライト 35人（月1–3回）、レギュラー 45人（週1–4回）、ヘビー 20人（週5回以上）
- 解釈上の注意：想定データのため因果関係は示さない。実査では未回答者・新規ユーザーの偏りを別途確認する。

## 2. エグゼクティブサマリー

- 総合満足度（4・5点）：**74人（74%）**、平均 **3.91 / 5**
- 継続利用意向（「続けたい」「とても続けたい」）：**78人（78%）**
- NPS：**+11**（推奨者36人 − 批判者25人）
- 最も評価された価値：**頭の中が整理されていなくても記録できる（4.21 / 5）**
- 最大の改善機会：**AIが文脈を提示するまでの速さ・分かりやすさ**、および**最初の数週間の価値実感**
- 判断：コアコンセプト（「整理しない自由」「静かな伴走」）は支持されている。次は「記録する」から「役に立ったと実感する」までの時間を短くする。

## 6. 改善優先順位

Impact（満足度への影響）× Effort（実装負荷）で、まず90日以内に着手する項目を選ぶ。

### P0：最初の価値実感を早める（高Impact／中Effort）

1. 初回オンボーディングに「3分で3件」ミニ導線を追加。
2. 5件・10件・20件の節目で、何が見えるようになったかをプレビュー表示。
3. 空の状態に、入力例（気持ち・会話・メモ・問い）と所要時間を表示。

**成功指標（次回コホート比）**：初週3件到達率 +15pt、初週満足度4・5点 +10pt、4週継続率 +8pt。

### P1：AI提案を「信頼できる伴走」にする（高Impact／中〜高Effort）

1. 提案に「この記録からそう考えた理由」を1行表示。
2. 「弱める／別案／今回は不要」などのフィードバックをワンタップ化。
3. 断定表現を避け、提案の頻度・トーンを設定可能にする。

**成功指標**：提案の有用度4・5点 +12pt、提案スキップ率 −20%、AI関連の不満回答 −30%。

### P1：通知・静かな戻りの制御（中〜高Impact／中Effort）

- 通知の曜日・時間帯・最大頻度、再浮上を避けたいテーマを設定。
- 「なぜ今この記録か」を表示し、非表示・再表示の操作を学習に反映。

### P2：連携と透明性（中Impact／低〜中Effort）

- Discord接続を段階式にし、権限・同期範囲・解除方法を接続前に明示。
- 設定画面にデータ利用範囲、AI処理、エクスポート／削除の導線を集約。

## 7. 次回の実査プロトコル

1. 利用7日目と28日目に同じ5問を提示し、時系列変化を測る（同一ユーザー追跡）。
2. 回答率を上げるため、必須は5問以内、自由回答は任意にする。
3. 機能を使った人だけに機能別質問を出し、未使用者を低評価に混ぜない。
4. 満足度だけでなく、初回価値実感までの日数、週次記録数、提案への反応をイベント計測する。
5. n=100では割合の95%信頼区間は概ね±10ポイント（最悪ケース）と扱い、5ポイント未満の差は結論にしない。

2. 今後4週間も利用したいと思いますか（1〜5）。

## 結論

YOHAKUOSの核である「未整理のまま置ける」「過去と静かに再会できる」は、100人想定でも十分に支持される。一方、満足度を押し下げるのはコンセプトではなく、価値が現れるまでの待ち時間、AI提案の説明不足、通知・連携のコントロール不足である。次のリリースでは、**初週の価値実感 → 提案への信頼 → 通知の自己決定**の順に改善し、同じ設問と行動ログで効果検証する。
