## 現行画面で利用者に案内できる基本手順

1. 思いつきを残す：右下の「＋」→「メモを保存」→入力して保存。
2. メモを見返す：ホーム下部「詳細は必要時に開く」の「開く」→「YUI Feed」。
3. やることを決める：現在の目的の「＋ 次のタスクを追加」→入力して追加。終えたらそのタスクの「完了」。進捗表示には上記の不整合がある。
4. 結果を残す：現在の目的の「振り返りを記録」→入力して保存。詳細の「今日のReflection」で見返す。
5. AIに相談する：AI設定が利用可能になってから「YUIに話す」に入力し「保存して送る」。今回のアカウントは未設定で、相談回答を得られなかった。

## 改善の実施順

1. AI利用可否の事前表示、エラーの記憶候補化防止、完了・進捗の不整合、過去時間提案を修正する。
2. 入力欄を上部へ移し、保存完了と記録へのリンクを付ける。ヘルプを実際の操作ガイドにする。
3. 用語を統一し、詳細カードを整理する。「話す・今日やること・振り返る」を基本導線にする。
4. 改善後に、新規アカウント・AI利用可能アカウント・スマートフォン実機で再評価する。

## 改善後の評価方法

初見の利用者に「今週やりたいことを入力し、今日やることを1つ決めてください」とだけ伝える。相談開始までの時間、支援なしで完了できた割合、迷った操作、保存した内容を再発見できるかを記録する。提案する目標値は相談開始まで60秒以内、5人中4人以上が支援なしで基本操作を完了。これは今後の評価基準であり、今回の測定結果ではない。

## 改善実装（2026-09-06）

優先課題の修正を実装し、本番サイトへデプロイ済み。

- ホーム上部に相談欄と3段階の使い方を配置。長文のまとめは折りたたみ。
- AI設定の確認中・未設定・取得失敗を区別して表示。未設定時は相談送信を無効にし、設定リンクとAIなしのメモ操作を案内。APIでも未設定時は保存前に拒否する。
- AI生成失敗の案内を通常の応答として保存しない。既存の定型エラーは会話取得と記憶候補取得から除外。
- 会話送信後の時間提案の自動生成を停止。時間提案は明示操作で生成。
- 目標一覧とホームの進捗を共通計算へ統一（手動の進捗とタスク完了率の大きい方）。完了・保留タスクを「次の一歩」の候補から除外。
- 「最近の記録」を常時表示。メモ・振り返り保存後の完了案内と「記録を見る」リンクを追加。
- 相談履歴の4件制限を外し、取得済み履歴をスクロールで見返せるようにした。
- 未接続の予定・メールを0件と表示しない。設定案内に外部連携が任意であることを明記。
- 時間提案は利用者のタイムゾーンで今後14日間の9〜18時を調べ、現在より後の空き時間に指定分数（未指定は30分）だけ確保。空きがなければ架空の代替枠を作らない。
- 期限切れの保留時間提案を一覧から除き、承認時にも期限を検証。AIが生成する時間枠も未来・指定時間内・空き枠内に制限。
- 相談から生じた予定作成依頼は、確認待ちの提案として保存する。時間提案の承認も予定登録候補を作るところまでに留め、Google Calendarへ書き込むのは「Google Calendarに登録する」の明示操作だけにした。
- `/help` に実際のボタン名を使った操作ガイドを追加し、「ヘルプ・使い方」のリンク先を修正。
- 主要操作のReflection表記や記憶採用ボタンを日本語へ変更。詳細の一部の開発用説明も修正。

検証結果：`npm run typecheck` 成功、回帰テスト7件成功、`npm exec -- next build` 成功、`git diff --check` 成功。ローカルブラウザで使い方ページとホームの相談欄・AI未設定案内・最近の記録・未接続表示を確認。スマートフォン幅でも確認した。本番テストアカウントでも、相談欄の事前案内、最近の記録、未接続表示、進捗表示、使い方ページを確認した。

料金画面には無料版とPremiumの違い、AI利用条件、保存期限の対象を追加した。新規登録時の入口は、特定の職業や状況を前提にせず「日々のこと」「新しい挑戦」「環境の変化」から選べるようにした。
